# 主題
基於少樣本(few-shot)影像辨識之 AI 智慧庫存管理系統

# 專題背景
傳統庫存管理依賴人工盤點，容易發生：
- 人工輸入錯誤
- 盤點速度慢
- 商品遺漏

因此利用 AI 影像辨識，輔助人工盤點，維持實際狀況與庫存資訊的同步。
適用個人小店、小型倉儲，像是：小型五金行、工具室、學校實驗室。

# 研究目的
利用影像辨識輔助盤點庫存，避免人工錯誤。
建立庫存管理系統，提供出入庫、盤點、查詢庫存操作，維持資訊同步。

系統情境固定為庫存管理，但不限定物品種類：品項目錄由使用者自行維護（新增、命名、分類），不寫死於特定領域（可以是電子零件、也可以是手工藝材料等其他實體庫存物品）。新增品項時，只需提供幾張參考照片即可讓系統立即認得（少樣本辨識，不需重新訓練模型），系統在正常出入庫過程中持續累積「模型初步辨識 → 人工確認/修正」的紀錄；累積足量資料後，可視需要另外對物件偵測部分進行模型微調（fine-tune），進一步改善辨識品質。整個新增品項的過程僅透過操作介面完成，不需使用者具備程式能力。

# 系統設計理念

系統依工作性質分成兩部分：

- **現場出入庫流程（自行開發）**：拍照 → 模型初步辨識 → 使用者輕量確認/修正（僅需確認類別與數量，不要求標註物件位置）→ 更新庫存數量。此流程與庫存業務邏輯緊密綁定，且需嵌入日常操作、不打斷使用者原本的工作目的，因此為系統自行開發的核心部分。
- **標註後台（整合現成工具）**：現場快速修正不要求框選物件位置（bounding box），若之後需要更精細的物件偵測模型微調，才需要另外補齊、校正 bounding box 作為訓練資料。此作業獨立於日常操作之外，且屬於已有成熟解法的通用問題，故規劃整合現成標註工具（如 Label Studio）處理：透過其 API 匯入待標註資料（並帶入模型原始預測作為預標註，減少標註者工作量），標註完成後匯出結果寫回系統。不自行開發標註介面。

此設計將「與庫存情境緊密相關、需嵌入日常操作」的部分（現場流程）與「通用、已有現成工具可解決」的部分（詳細標註）分開，避免重複造輪子，並將開發資源集中在系統整合與庫存情境本身。

辨識能力本身（拍照找出物件、比對已知類別）設計為獨立服務，不綁定庫存這一種應用邏輯——庫存管理是目前開發並驗證這套服務的示範應用（demo application），理論上同一套辨識服務未來也可以支援其他情境（例如手工藝拼豆的圖案輔助/校對），詳見下方「需求與限制」。

# 部署概念

除模型訓練/微調（於 Colab/Kaggle 等具 GPU 資源的環境離線進行）與標註後台（Label Studio，屬低頻的離線作業，非日常操作必要服務）外，系統其餘部分（辨識服務、資料庫、前後端）力求能運行於經濟實惠的邊緣運算硬體（以 Intel N100 等級設備為基準），降低小型店家、實驗室導入的成本門檻：

- 推論採 CPU 執行，搭配輕量化技術（模型量化、推論加速引擎等）進一步降低延遲與資源用量
- 各服務以 Docker Compose 拆分部署，依硬體資源調整
- 系統互動模式為「拍照觸發辨識」，非即時影像串流，降低對硬體效能的要求

# 技術組合

- 後端服務：FastAPI + PostgreSQL（SQLAlchemy、Alembic 管理 migration）
- 物件候選框偵測：FastSAM（不綁定特定類別，只負責找出畫面中「有東西」的位置）
- 少樣本分類：DINOv2（自監督視覺特徵抽取，用少量參考圖比對辨識新類別，不需重新訓練）
- 推論引擎：ONNX Runtime，搭配量化等輕量化手段
- 部署：Docker Compose

# 需求與限制

1. **獨立服務設計**：辨識服務不綁定特定應用邏輯，理論上可支援不同情境，例如：
   - 拚豆輔助 APP（拍照算出設計圖、輔助逐步放樣設計圖、錯誤糾正）
   - 庫存管理（目前的示範案例）
2. **邊緣運算**：以 N100 等級硬體為效能基準
3. **跨領域辨識**：不限定電子零件、手工藝材料、拼豆等特定物品類型
4. **運作中優化**：新增/修正參考圖後，辨識能力要能即時反映，不需重新訓練、不需重啟服務
5. **未來可微調**：持續記錄掃描結果與人工確認/修正紀錄，累積足量資料後，可透過雲端 GPU 資源對模型進行微調

# 功能
以”學校實驗室”為例。
1. 物品入庫
新購買的設備或耗材送達研究室後，管理者選擇入庫功能。
使用攝影機拍攝物品，系統辨識物品種類與數量。
管理者確認結果後，系統更新庫存數量。
2. 物品借出
學生或研究人員領取耗材、借用設備時，選擇出庫或借用功能。
系統辨識物品，或由使用者選擇物品名稱。
輸入領用數量、借用人與用途。
系統扣除庫存，或將設備狀態改為借出。
3. 物品歸還
借用人歸還設備時，選擇歸還功能。
確認設備名稱、數量與使用狀況。
系統將設備狀態更新為已歸還，並記錄歸還時間。
4. 盤點
管理者定期拍攝研究室內的工具櫃、零件櫃或耗材存放區。
系統辨識畫面中的物品種類與數量。
系統將辨識結果與資料庫紀錄進行比對。
顯示數量一致、短缺、遺失或位置錯誤的物品。
5. 庫存與設備查詢
使用者可依物品名稱、類別或存放位置進行查詢。
查看目前數量、借用狀態、借用人及最近異動紀錄。
協助學生快速找到所需設備或耗材。
6. 低庫存提醒
當網路線、接頭、感測器、開發板或其他耗材低於最低庫存量時，系統顯示提醒。
管理者可依提醒安排採購或補充。
7. 庫存變化紀錄
系統保存每次入庫、領用、借出、歸還、盤點與人工修正紀錄。
管理者可查詢操作時間、物品名稱、數量、使用者與操作類型。
