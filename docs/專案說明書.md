# 主題
基於少樣本類別增量學習之通用視覺辨識服務，以智慧庫存管理系統作為示範應用

# 專題背景
固定集合視覺辨識系統的類別於訓練時就已固定，新增類別需重新蒐集資料、重新訓練模型。此限制使其難以套用在類別會持續變動的場景，例如庫存管理：品項隨時間新增、下架、規格變更。

本專題採用少樣本類別增量學習(Few-Shot Class-Incremental Learning)，辨識目錄(系統已知的可辨識項目集合)可於運作中新增、移除、修改，新增項目僅需數張參考照片，不需重新訓練即可生效。以智慧庫存管理系統作為示範應用，驗證此辨識能力於實際場景的可用性，適用對象：小型五金行、工具室、學校實驗室等小規模庫存場景。

# 研究目的
1. 運作中修改辨識目錄：新增、移除、修改辨識目錄中的項目。新增項目(註冊，enrollment)僅需數張參考照片，不需重新訓練、不需重啟服務。
2. 運作中優化比對策略：以難例挖掘(hard-negative mining)找出常被誤判的參考樣本並汰換，補入更具代表性的樣本；依歷史誤判紀錄以主動學習(active learning)方式調整比對策略。
3. 分類蒐集微調(fine-tune)用資料集：依人工修正類型(身分修正、定位修正、誤判排除)分類儲存「模型初判 → 人工確認/修正」紀錄。
4. 低規格邊緣裝置之軟硬體最佳化：以CPU推論為前提，評估模型量化、推論引擎等技術組合，於低規格邊緣裝置上達到可用延遲。微調等高運算量工作外包至雲端GPU資源，邊緣裝置不承擔訓練負載。
5. 辨識服務獨立於應用邏輯：核心辨識能力(拍照定位物件、比對辨識目錄)為獨立服務，不綁定庫存管理這類特定應用邏輯，可用於其他需辨識能力的應用。

# 部署概念
模型訓練/微調於Colab/Kaggle等具GPU資源環境離線進行，系統其餘部分運行於邊緣裝置。架構分三部分：

- **裝置**：邊緣運算裝置(執行辨識服務、資料庫、前後端、標註後台)，搭配手機、平板等具相機的行動裝置(僅作拍照介面，透過瀏覽器操作，不需另外安裝App)
- **容器**：各服務以Docker Compose拆分部署，依硬體資源調整
- **網路**：各裝置間透過區域網路(LAN)通訊，日常操作不需連外網；系統互動模式為拍照觸發辨識，非即時影像串流，降低硬體效能需求


# 技術組合
- 辨識服務：FastAPI + SQLite
- 庫存管理服務：Flask + SQLite
- 物件候選框偵測：FastSAM，不綁定特定類別，僅偵測畫面中物件位置
- 少樣本分類：DINOv2，自監督視覺特徵抽取，比對少量參考圖辨識新類別，不需重新訓練
- 推論引擎：ONNX Runtime，搭配模型量化等技術降低運算量
- 部署：Docker Compose，各服務獨立容器化

# 需求與限制
1. **獨立服務設計**：辨識服務不綁定特定應用邏輯，可支援不同情境，例如：
   - 拚豆輔助APP(拍照比對設計圖、標示錯誤)
   - 智慧庫存管理(本專題示範應用)
2. **邊緣運算**：以低規格邊緣裝置為效能基準
3. **跨領域辨識**：不限定電子零件、手工藝材料、拼豆等特定物品類型
4. **運作中優化**：新增/修正參考圖後，辨識能力即時反映，不需重新訓練、不需重啟服務
5. **未來可微調**：持續依人工修正類型分類記錄「模型初判 → 人工確認/修正」結果，累積足量資料後可透過雲端GPU資源微調模型

# 功能
以「學校實驗室」為例。

1. **物品入庫**
   新購買的耗材送達後，管理者選擇入庫功能。使用攝影機拍攝物品，系統辨識物品種類與數量。管理者確認結果後，系統更新庫存數量。
2. **物品出庫**
   領用耗材時，選擇出庫功能。系統辨識物品，或由使用者選擇物品名稱，輸入領用數量。系統扣除庫存數量。
3. **盤點**
   管理者定期拍攝工具櫃、零件櫃或耗材存放區。系統辨識畫面中的物品種類與數量，與資料庫紀錄比對，顯示數量一致、短缺或遺失的品項。
4. **庫存查詢**
   使用者可依物品名稱、類別或存放位置查詢，查看目前數量與最近異動紀錄。
5. **低庫存提醒**
   當網路線、接頭、感測器、開發板或其他耗材低於最低庫存量時，系統顯示提醒，供管理者安排採購或補充。
6. **庫存變化紀錄**
   系統保存每次入庫、出庫、盤點與人工修正紀錄，可查詢操作時間、物品名稱、數量、使用者與操作類型。

- **現場出入庫流程**：拍照 → 模型初判 → 人工確認(類別與數量，不要求標註物件位置)→ 更新庫存數量。初步標註留待標註後台精修。
- **標註後台**：提供精修標註介面，結案標註可匯出作為訓練資料集。
