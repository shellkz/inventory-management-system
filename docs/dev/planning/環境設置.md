# 環境設置(不含攝影機/go2rtc部分)

## 1. 安裝需求

- Docker + Docker Compose

## 2. Clone兩個repo

```
git clone https://github.com/shellkz/inventory-management-system
git clone https://github.com/shellkz/sharingan-vision
```

確認兩個repo的相對路徑跟`docker-compose.yml`裡`build: ./inventory`、`build: ./vision-service`的對應關係一致(inventory-management-system底下要有`vision-service`這個目錄名稱指向sharingan-vision)。

## 3. 下載模型檔

在inventory-management-system根目錄建立`models/`資料夾,從sharingan-vision的GitHub Release下載這兩個檔案放進去:

- `FastSAM-s_640_fp32.onnx`
- `dinov2_vits14_batch_int8.onnx`

```
gh release download v0.1.0 -R shellkz/sharingan-vision -D models/
```

下載後可以用`sha256sum`核對checksum(如果有提供的話)。

## 4. 設定`.env`

複製`.env.example`為`.env`,填入:

```
VISION_API_KEY=<自己產生,例如 openssl rand -hex 32>
FASTSAM_ONNX_PATH=models/FastSAM-s_640_fp32.onnx
DINOV2_ONNX_PATH=models/dinov2_vits14_batch_int8.onnx
VISION_SERVICE_URL=http://vision-service:8000
```

`VISION_API_KEY`inventory跟vision-service要用同一個值,因為是inventory呼叫vision-service時的認證key。

攝影機相關的`CAM_USER`/`CAM_PASS`/`CAM_PATH`/`CAM1_IP`**先留空不用填**——go2rtc這個服務目前沒有被`inventory`/`vision-service`依賴(`depends_on`沒有包含go2rtc),就算go2rtc因為缺設定而連不上真實攝影機,不影響其他服務正常運作。

## 5. Build & 啟動

```
docker compose build
docker compose up -d
```

`inventory`會在啟動時自動跑`alembic upgrade head`,不用手動建DB schema。

## 6. 驗證

瀏覽器開`http://localhost:5000/items`確認頁面正常;也可以打`http://localhost:5000/api/items`確認API正常回傳。
